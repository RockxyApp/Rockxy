# Sessions & HAR

Rockxy supports saving and restoring captured traffic in two formats: the native `.rockxysession` format for full-fidelity session files, and the industry-standard HAR (HTTP Archive) format for cross-tool compatibility.

## Native .rockxysession Format

Rockxy's native format preserves the full session including metadata, user annotations, and all captured transactions.

| Action | How to Access |
|--------|---------------|
| Open Session | **File > Open Session...** (`Cmd+O`) |
| Open Recent | **File > Open Recent** lists sessions and HAR files you opened or saved (also in the Dock menu); **Clear Menu** empties it |
| Save Session | **File > Save Session...** (`Cmd+Shift+S`) |

### What .rockxysession Preserves

| Data | Preserved |
|------|-----------|
| Transactions (URL, method, headers, body, status) | Yes |
| Timing info (DNS, TCP, TLS, TTFB, transfer) | Yes |
| WebSocket frames | Yes |
| GraphQL operation info | Yes |
| Log entries | Yes |
| User comments | Yes |
| Highlight colors | Yes |
| Strikethrough marks | Yes |
| Pinned/saved status | Yes |
| TLS failure flags | Yes |
| Client app name | Yes |
| Session metadata (dates, version, count) | Yes |

### Saving a Session

1. Capture traffic as usual.
2. Choose **File > Save Session...** (`Cmd+Shift+S`).
3. Pick a location and filename. Rockxy writes a `.rockxysession` file.

The file includes all captured transactions, log entries, user annotations (comments, highlight colors, pinned/saved status), and session metadata (capture date range, transaction count, Rockxy version).

### Opening a Session

1. Choose **File > Open Session...** (`Cmd+O`) and select a `.rockxysession` file.
2. Rockxy shows an **Import Review** sheet with file metadata (name, type, request count, file size) and a warning if the current session is non-empty.
3. Click **Replace Current** to load the session, or **Cancel** to abort.
4. The loaded transactions appear in the traffic list with all annotations (comments, highlights, pins) restored. The status bar shows the import source.

## HAR Format

HAR is a JSON-based format supported by browser DevTools, Charles Proxy, Proxyman, mitmproxy, and other network tools.

| Action | How to Access |
|--------|---------------|
| Import HAR | **File > Import HAR...** (`Cmd+Shift+I`) |
| Export HAR | **File > Export HAR...** (`Cmd+Shift+E`) |

### Importing a HAR File

1. Choose **File > Import HAR...** (`Cmd+Shift+I`).
2. Select a `.har` or `.json` file, a Charles JSON session (`.chlsj`, from Charles's **File > Export Session… > JSON Session File**), or a binary Charles session (`.chls`).
3. Rockxy shows an **Import Review** sheet with file metadata and a destructive warning if you have an active session.
4. Click **Replace Current** to import, or **Cancel** to abort.
5. Imported transactions appear in the traffic list. The status bar shows the import source.

Import errors (invalid format, oversized file, deserialization failure) are shown in a dialog with a specific error message.

A Charles JSON session keeps each request's headers, body, response, timings, and — where Charles recorded them — the server address and TLS version, which appear in the [Connection Log](/features/connection-log). You can also drop a `.chlsj` file on the traffic list.

`.chls` is Charles's own binary format, so Rockxy asks the Charles installed on your Mac to convert it to HAR and imports the result. The first time, Rockxy explains this and asks before running the converter; Charles runs in the background without opening a window or changing proxy settings, which takes a few seconds. If Charles isn't installed, Rockxy says so — export the session from Charles as `.chlsj` or `.har` instead. Dropping a `.chls` on the traffic list and **File > Open Recent** work the same way.

### Exporting to HAR

1. Choose **File > Export HAR...** (`Cmd+Shift+E`).
2. An **Export Scope** sheet lets you choose what to export:
   - **All Transactions** — everything captured
   - **Visible / Filtered** — only what the current filter shows
   - **Selected** — only selected transactions
3. To share the file safely, turn on **Redact sensitive data**. Rockxy replaces recognized secrets — `Authorization`, cookies, API keys, URL tokens, and secret body values — with `[REDACTED]` in the file; your captured session keeps the original values. The same option is offered for Rockxy Session, CSV, and Postman exports.
4. Click **Export...** to open the save dialog.
5. Pick a location and filename. Rockxy writes a standard HAR 1.2 file.

You can also export from the request list: right-click a request and choose **Export > Export as HAR...**. When the clicked request is part of a multi-row selection, the menu reads **Export Selected as HAR...** and writes every selected request.

### Exporting Part of a Session

**Save Session** always writes the whole capture, including logs. To share only some requests with full fidelity (headers, bodies, timing, notes, and highlights):

1. Select the requests, then right-click and choose **Export > Export Selected as Rockxy Session...**; or choose **File > Export Rockxy Session...** and pick **Selected** or **Visible / Filtered** in the Export Scope sheet.
2. Pick a location. The recipient opens the `.rockxysession` file by double-clicking it or dropping it onto Rockxy.

In the sidebar, right-click a domain or an app and choose **Export > as Rockxy Session...** or **Export > as HAR (HTTP Archive)...** to export only its requests. **Export > Export as CSV...** in the request list works the same way for a one-row-per-request summary.

### Postman collections

Choose **Flow > Export > Export as Postman Collection…**, or right-click requests and choose **Export > Export Selected as Postman Collection…**, to save them as a Postman Collection (v2.1) that Postman and compatible API clients import. Requests are grouped in one folder per host; each keeps its method, URL, query, headers, and text body, and its captured response is attached as a saved example. `Host`, `Content-Length`, and proxy headers are left out so edited requests stay valid. CONNECT tunnels and WebSocket connections are skipped, and binary request bodies are noted rather than included. The file contains authorization headers and cookies, so review it before sharing.

<Note>
  Exported HAR files may contain request bodies, cookies, and authorization headers. Review exports before sharing.
</Note>

## Other Export Options

Beyond file-level session save/export, Rockxy supports copying individual requests via the right-click **Copy as** submenu in the request list:

- **JSON** — structured JSON representation.
- **HAR Entry** — single-request HAR entry payload.
- **Raw Request** / **Raw Response** — full HTTP/1.1 text dump of either side.
- **Request Headers** / **Response Headers** / **Request Body** / **Response Body** / **Request Cookies** / **Response Cookies** — surgical clipboard copies.
- **Copy as cURL** — available from **Edit > Copy as cURL** (`Cmd+Shift+C`) for the selected request.

## Limitations

- HAR export includes HTTP transactions only. WebSocket frames, GraphQL metadata, log entries, and user annotations (comments, highlights) are not included in HAR files. Use `.rockxysession` for full-fidelity saves.
- `.rockxysession` files are not compatible with other tools — use HAR for cross-tool sharing.
- Bodies larger than 10 MB are marked as truncated in `.rockxysession` files. For full-fidelity capture of very large bodies, keep the local app data until you are done debugging.
- Large sessions with many transactions may take a few seconds to save or load.
