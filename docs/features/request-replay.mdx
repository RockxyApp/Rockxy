# Request Replay

Rockxy can re-send any captured HTTP or HTTPS request. There are two replay paths: **Repeat** sends the request again immediately, and **Edit and Repeat** opens an editable sheet where you can change the method, URL, headers, and body before sending.

Replay uses a proxy-bypass session (an ephemeral `URLSession` with proxy settings disabled), so replayed traffic does **not** re-enter Rockxy's proxy pipeline. This avoids infinite loops and means active rules (breakpoints, throttle, header modifications) do not apply to replayed requests. Each Repeat still lands in the traffic list as a new row attributed to Rockxy, so the fresh response can be inspected, diffed, and exported next to the original.

## Entry Points

| Action | How to Access |
|--------|---------------|
| Repeat | Right-click a request > **Repeat**, or **Flow > Repeat** (`Cmd+R`) |
| Edit and Repeat | Right-click a request > **Edit and Repeat...**, or **Flow > Edit and Repeat...** (`Cmd+E`) |

## Repeat (Fast Replay)

**Repeat** re-sends the selected request with the same method, URL, headers, and body as the original. No editing step — the request goes out immediately.

1. Select a request in the traffic list.
2. Right-click and choose **Repeat**, or press `Cmd+R`.
3. A new row attributed to Rockxy appears in the traffic list with the replayed request and its response; select it to inspect status code, headers, and body. A toast summarizes the status code.

### Repeat several requests

Select several rows (Shift-click or Command-click), then press `Cmd+R` or right-click one of them and choose **Repeat**. Rockxy sends them one after another in list order, adds each result as its own row, and shows one summary of how many were sent, failed, or could not be repeated (for example WebSocket rows). One Repeat sends at most 50 requests.

### Repeat through your rules

**Repeat** goes straight to the server, so no rules apply. To see how your Breakpoint, Map Local, Map Remote, Block List, Scripting, and Modify Headers rules treat a request, choose **Flow > Repeat Through Rules** or right-click and choose **Repeat Through Rules**. Rockxy sends the request (or every selected request) through its own proxy listener, so the rules apply and the proxy records each one as a new row. The proxy must be running. For HTTPS, the request is decrypted only when HTTPS decryption is on for its host and the Rockxy root certificate is trusted on this Mac.

## Edit and Repeat

**Edit and Repeat** opens a sheet where you can modify the request before sending:

- **Method** — switch between GET, POST, PUT, DELETE, PATCH, or any custom method.
- **URL** — change the scheme, host, path, or query parameters.
- **Headers** — add, remove, or edit any header. Click **+** to add a new row.
- **Body** — edit the request body with syntax highlighting for JSON, XML, and form data. When `Content-Type` is `application/x-www-form-urlencoded`, switch the Body tab to **Form** to edit fields as a name/value table; Rockxy encodes them the way browsers send forms.
- **Raw** — edit the whole request as HTTP text (request line, headers, blank line, body) and click **Apply** to update the other tabs, or **Revert** to discard the edit. A path in the request line is combined with the `Host` header; a full URL in the request line is used as is.

Click **Send** to dispatch the modified request, or **Cancel** to discard changes. Like a Repeat, each send also lands in the traffic list as a new row attributed to Rockxy (while recording is on), so an edited request can be inspected, diffed, and exported — for example, import a browser HAR, edit one request, then export the session as HAR again.

<Tip>
Use Edit and Repeat to test authentication flows. Copy a request, swap the Authorization header with a different token or remove it entirely, and check how the server responds.
</Tip>

## Viewing Results

The response is displayed inline in the replay sheet. It includes:

- **Status code** with the standard color badge (2xx green, 3xx blue, 4xx orange, 5xx red).
- **Response headers** in a key-value list.
- **Response body** with the same rendering as the main inspector (JSON tree, hex, text, image preview).

## Limitations

- **Repeat** bypasses the proxy, so it is not subject to active rules; use **Repeat Through Rules** when they should apply. Repeat rows are attributed to Rockxy rather than to the original client application.
- Replay sends a single request. Sequence recording (replaying a chain of dependent requests) is not yet available.
